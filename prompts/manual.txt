## Footnote linking — what postprocess handles automatically

- `* ** ***` symbolic footnotes (footnote item text must start with `*`, not `(*)`)
- Unicode superscript digits `¹²³` in body text — normalized then linked
- `<sup>N</sup>` numeric markers in body text — linked per-page sequentially
- Chapter-scoped endnotes under a "Notes on text sources" chapter title (Case 2)
- Splitting packed footnote items that contain multiple Unicode-sup-separated entries

## Running footnotes (spanning multiple pages)

step7 automatically detects and merges footnotes that start on one page and continue on the next.

**Detection rule:** for each page, step7 scans body text (main_text, chapter_title, subtitle) for inline footnote markers (`<sup>` tags, Unicode superscripts). A footnote area whose leading marker is absent from that page's body markers is treated as a continuation of the previous open footnote and its text is appended to it. Pages 16–18 will not produce orphan footnote items for a footnote that originated on page 15.

**Manual overrides** (set on a footnote area object in JSON):
- `"is_running_continuation": true` — force this area to be merged into the preceding footnote even if a leading marker is present (e.g. OCR introduced a spurious marker)
- `"is_running_continuation": false` — force this area to start a new footnote even if no leading marker was detected

**Known limitation:** if the AI detection in step2 groups a continuation segment and a new page footnote into a single footnote area (one JSON object), the entire area is treated as continuation and the embedded new footnote is absorbed into it. Fix: split the area into two separate footnote area objects in JSON review before re-running step7.

## Footnote linking — what requires manual pre-processing in JSON

- `(*)`-style footnote markers: `_leading_marker()` does not recognise them.
  Solution: pre-number all footnotes in JSON with sequential `<sup>N</sup>` markers
  using a book-specific script (see `fix_json.py` in the book directory as reference).
- Per-page `*` footnotes where multiple pages each have their own `*`: postprocess
  matches sequentially across the whole document, which breaks page-local pairing.
  Same solution: pre-number in JSON before running postprocess.
- Combined footnote areas in `<sup>N</sup>` format (not Unicode sups): postprocess
  cannot split these automatically. Split them into separate JSON area objects.

Некоторые footnotes могут быть пропущены, или же наоборот цифра в тексте понята как footnote index, из-за чего нумерация всех сносок может быть поехавшей.
